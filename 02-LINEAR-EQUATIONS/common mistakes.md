# Common Mistakes — Linear Equations

## 1. Distributing to only one term inside the parentheses

`3(x + 2)` means multiply **both** terms inside by 3.

Wrong: `3(x + 2) = 3x + 2` ❌ (forgot to multiply the 2)
Right: `3(x + 2) = 3x + 6` ✓

## 2. Losing the sign when subtracting a group

`7 - 3(x - 2)` requires distributing the `-3` across *both* terms inside the parentheses, including flipping the sign of `-2`.

Wrong: `7 - 3x - 2` ❌ (the `-2` should become `+6`)
Right: `7 - 3x + 6` ✓

This is the same trap as "forgetting to distribute a negative" from Module 01, just with a coefficient other than 1.

## 3. Only moving variable terms partway

When variables appear on both sides, you must fully collect them onto one side before dividing. A common half-step mistake:

Wrong: `5x - 3 = 2x + 9` → subtract 2x → `3x - 3 = 9` → then dividing by 3 immediately without dealing with the `-3` first ❌
Right: subtract `2x`, **then** add 3 to both sides, **then** divide ✓

Order matters: clear addition/subtraction terms before dividing by the coefficient.

## 4. Cross-multiplying incorrectly

For an equation like `(x - 2)/3 = 5`, there's no second fraction to cross-multiply against — just multiply both sides by 3 directly.

Cross-multiplication (`(2x+1)/3 = (x-2)/2` → `2(2x+1) = 3(x-2)`) only applies when there's a fraction on **both** sides. Using it when only one side is a fraction is unnecessary and invites arithmetic errors.

## 5. Assuming every equation has exactly one answer

Not recognizing "no solution" or "infinite solutions" as valid outcomes is one of the most common gaps at this stage. If both sides fully simplify to the same expression with `x` cancelling out entirely, check whether what remains is:
- **False** (like `-6 = -2`) → no solution
- **True** (like `2 = 2`) → infinite solutions

Don't assume you made an error just because `x` disappeared — sometimes that's the correct outcome.

## 6. Forgetting to check the answer

Especially on multi-step problems, plugging your answer back into the *original* equation (not a simplified version) is the fastest way to catch an arithmetic slip before it costs you the whole problem.
